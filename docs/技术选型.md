# 技术选型 · NanoTab 轻起始页

> 日期：2026-11-01　依据：`PRD.md`
> 一句话结论：**纯静态 MV3 扩展，零服务器、零后端、0 元；产物就是一个文件夹，本地加载即用。**

---

## 一、三个必须先说清的问题

### ① 静态还是动态？要不要服务器？

**纯静态，不要服务器。**

| 判断依据 | 结论 |
| --- | --- |
| 有需要存进数据库的数据吗？ | 没有（单用户自用，无账号、无多人共享） |
| 要多设备看到同一份数据吗？ | 不需要（PRD 已定：纯本地 + 导出 JSON 迁移） |
| 要调后端接口吗？ | 不需要（搜索=跳转搜索引擎网址；图标=直连站点 favicon） |

所以：**无后端、无数据库、无 API**。整个产品就是一堆 HTML/CSS/JS，装进浏览器跑。
（对比云端壳方案：它是"云端网页 + 扩展壳"的动态架构，必须联网、必须养服务器——我们不走这条路。）

### ② 部署到哪里？

**不部署。** 分发方式只有两种：

| 方式 | 说明 | 何时用 |
| --- | --- | --- |
| 加载已解压的扩展 | `chrome://extensions` → 开发者模式 → 选 `dist/` | **第一版就用它** |
| 打包 zip | 把 `dist/` 压缩 | 备份 / 分享 / 日后上架 |

**没有域名、没有 HTTPS、没有 CDN、没有 GitHub Pages** —— 都不需要。这是插件相对网站的最大优势：天生装在本机。

### ③ 花多少钱？

**0 元。**

| 项目 | 费用 |
| --- | --- |
| 开发工具（Vite/React/TS 全开源） | 免费 |
| 运行（纯本地无服务器） | 免费 |
| 存储（chrome.storage.local） | 免费 |
| 自用不上架 | 免费 |
| 未来若上架 Chrome 商店 | 一次性 $5（≈36 元），PRD 已列为"不做" |

## 二、技术栈

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 扩展规范 | **Manifest V3** | Chrome/Edge 现在只接受 MV3，MV2 已停用 |
| 构建 | **Vite 7** | 快、配置简单、教程最多（Webpack/CRA 已过时） |
| UI | **React 19** | 已拍板；生态最丰富 |
| 语言 | **TypeScript 5** | 类型安全，改代码时 IDE 直接报错 |
| 样式 | **Tailwind CSS v4** + CSS 变量 | 改样式快；变量统一管主题色/明暗 |
| 图标 | **lucide-react** | 内联 SVG、按需打包、体积小（不用 emoji 当图标） |
| 状态 | `useState`/`useContext` + 自定义 hook | 数据量极小，不引 Redux/Zustand |
| 存储 | `chrome.storage.local` | PRD 已定纯本地 |
| 拖拽 | 原生 HTML5 `draggable` | 九宫格排序够用，不引 dnd-kit |
| 包管理 | npm + 国内镜像（npmmirror） | 避免 install 卡 4 分钟 |

**不引入**：后端、数据库、UI 组件库（shadcn/MUI 太重）、状态管理库、拖拽库、axios。

## 三、插件特有的关键决策（和写网站不一样，重点）

### 3.1 不用 `@crxjs/vite-plugin`，手写多入口

该插件对 React/Vite 版本敏感、出问题难排查。**我们把扩展当"多页 Vite 应用"构建**，`dist/` 直接可加载：

```ts
build: {
  rollupOptions: {
    input: { newtab: 'newtab.html', popup: 'popup.html', background: 'src/background/index.ts' },
    output: { entryFileNames: '[name].js', chunkFileNames: '[name].js', assetFileNames: '[name].[ext]' },
  },
},
```

> ⚠️ **必须关掉文件 hash**：`manifest.json` 里写死 `newtab.js`，若 Vite 输出 `newtab-a3f2.js`，扩展直接加载失败。这是插件开发最常见的坑。

### 3.2 Service Worker 极简

MV3 的 background 是 Service Worker，会被浏览器休眠。第一版**可以不写 background**；P1 加快捷键时再补，控制在 50 行内。

### 3.3 权限只申请一个

```json
"permissions": ["storage"]
```

不用 `tabs`（不碰别的标签页）、不用 `browsingData`（本地方案无需清缓存）、不用 `content_scripts`（不碰别人网页）、不用 `web_accessible_resources`。**权限越少越安全、越不吓人。**

### 3.4 MV3 的 CSP 硬约束

禁止内联脚本、`eval`、远程代码加载：
- ✅ Vite 打包出的外链 `.js`：没问题
- ❌ `<script>alert(1)</script>`：禁止
- ❌ CDN 引 React / Tailwind CDN 版：禁止（必须打包进本地）

### 3.5 favicon 抓取：直连站点，不用第三方服务

| 方案 | 国内可用 | 结论 |
| --- | --- | --- |
| `google.com/s2/favicons` | ❌ 常不通 | 弃用 |
| favicon.im 等第三方 | 一般 | 弃用 |
| **`https://{域名}/favicon.ico`** | ✅ | **采用** |

失败 → 降级显示"站点名首字"（彩色圆底白字），保证界面不破。

### 3.6 壁纸必须压缩后存 base64

`chrome.storage.local` 上限 **10 MB**。1920×1080 原图转 base64 可达 2-5 MB。
对策：Canvas 压缩（最长边 ≤1920，JPEG 0.85）；单张 >4 MB 提示改用 URL；写入失败捕获 `chrome.runtime.lastError` 并页面内提示。

## 四、开发与构建流程

| 环节 | 命令 | 说明 |
| --- | --- | --- |
| 装依赖 | `npm install` | 首次 |
| 开发 | `npm run dev` = `vite build --watch` | 生成 `dist/`，改代码自动重建 → 浏览器点"刷新" |
| 构建 | `npm run build` | 产出 `dist/` |
| 打包分发 | `npm run zip` | 压缩成 `nanotab-v1.0.0.zip` |
| 加载 | `chrome://extensions` → 加载 `dist/` | 验收方式 |

> 为什么不用 `vite dev server`：MV3 有 CSP 限制，dev server 直接加载会报错。用 `build --watch` + 刷新扩展最稳。

## 六、风险登记

| 风险 | 应对 |
| --- | --- |
| Node/Git 未装，阶段 4 会卡 | 阶段 4 优先安装并验证 `node -v` |
| Vite hash 导致 manifest 找不到文件 | 关闭 hash（3.1）；构建后校验 `dist/` 文件名 |
| 壁纸 base64 撑爆 10 MB | 压缩 + 超限提示 + 捕获写入错误 |
| Tailwind v4 与 Vite 集成配置 | 用官方 `@tailwindcss/vite` 插件，不用 PostCSS 老方案 |
| npm 安装慢 | 预设 npmmirror 镜像 |
